核心验收包含 **36 项**，最终执行结果见本节末的记录。

## 浏览器验收

`npm run test:browser` 使用真实鼠标拖拽而非向游戏注入测试弹药。包含 **9 个**浏览器场景：

- 正常模式启动、必需资源无 404、控制台无脚本错误、五关切换。
- 刻意阻断 Matter 或破坏入口脚本：显示明确错误，不留下无提示白屏。
- 拖拽投掷、弹药脱离、剩余发数、重开。
- 四种弹药及圆石最终睡眠；实际音频 `.play()` 成功，未发生解码/播放拒绝。
- 五关初始与 TNT 后画面、重开不泄漏刚体、暂停冻结物理时间。
- 左下拖拽方向、九格物品栏、人物实际位移、静态云像素不变。
- 滚轮首尾循环、空槽不发射、物品格宽高与图标范围；TNT 全引信闪白和连续步态另有核心回归。
- 实际鼠标高抛珍珠与黑洞攻击完成木屋、哨塔挑战。
- 弹弓版通关在真实鼠标操作下复测，攻击序列与存活怪物诊断保存在 `browser-victories.json`。

## 启动与审查

- 实际运行 `START_GAME.bat`（隐藏测试控制台、独立端口 18766）：Node 服务正常启动，HTTP 200；验证后停止该测试进程。日常预览在 8766，由项目自带 Node 服务器提供。
- 独立代码审查发现并复现三处边界问题：旋转残骸速度漏算、微小孤岛后墙残留、动态残骸使预览缓存过期。均增加先失败后通过的回归；审查者只读复核三处修复，29/29 核心用例通过。五关获胜回放为之后增加的第 30 项。
- Windows Playwright trace 曾遇到 EBUSY，故关闭 trace，保留失败截图、人工检查截图与 JSON 诊断。
- GitHub CI 配置已提供；本机结果不代表远端 CI 已执行成功。

补充：整座建筑的承重截面检查通过屋脊炸断回归；步态不再量化为每周期 24 帧。黑洞场景复验发现巡逻控制抵消吸力，已改为吸引范围内由物理控制，并验证实际靠近核心。完整浏览器通关测试会根据存活怪物位置调整后续鼠标瞄准，因此不会将一个固定角度偶然成功当作通关保证。

最后按用户要求换为木质弹弓：增加拉伸上限、弹药兜不进入地面和发射原点的核心测试；浏览器继续测试实际拉伸/松手、四种弹药、五关及回弹。独立复核弹兜原点、单次扣弹、回弹/暂停/重开、换关缓存，相关 24 项用例通过。当前性能诊断刷新后，本机四弹药场景约 74–75fps；缓存优化前为 29–48fps，数据不代表其他设备。
