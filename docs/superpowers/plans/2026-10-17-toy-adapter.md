# Toy 适配实施

目标：保持《MC打弹弓》十关玩法、唯一昵称和毫秒计时榜单，让 Toy 静态包可独立加载，并通过官方 SDK 同步同账号存档。

最终方案：自建站点继续保存原 Node 唯一昵称/毫秒榜；Toy 包不依赖家庭 API，改用 B 站账号和官方 SDK 原生榜单，完整十关最快总时长按 0.01 秒编码为只增分数。Toy 使用 getUserProfile/getCloudStorage/setCloudStorage：按 toyOpenId 隔离本机数据，启动读取，过关等关键节点合并写入，限流指数退避；云读取失败不自动覆盖云记录，离线可玩。原先 HTTPS CORS 方案已验证，但用户在真实预览反馈榜单不可连接，最终以原生 SDK 避免家庭公网/NAT 依赖。

1. 先添加真实 HTTP CORS 回归，验证允许 Toy 来源、拒绝其他来源、原同源与代理规则保持，然后实现服务配置。
2. 编写云存档模块及离线、账号隔离、合并、限流测试；接入现有读写入口，不改物理/关卡。
3. 添加可重复 Toy 构建脚本，esbuild 合并成普通 IIFE 脚本，避免 MJS MIME 差异；仅输出运行文件、相对路径、官方 SDK 和原生平台配置，不打入私有数据。
4. 在两个不同 Origin 下以真实浏览器测试跨站昵称/榜单和云恢复；完整核心测试与既有游戏/手机专项回归。
5. 生成 4:3 游戏截图封面，执行官方 doctor。核对 CLI 登录/已有作品，先上传预览，实际检查再让用户明确确认提交审核。技能要求预览确认之后才能加 --yes。

只在本地保留构建目录，不生成额外 Windows 导出包。自建服务部署保持数据目录和现有链接不变。若平台 CSP 不允许自建 API，必须据真实预览结果调整方案，不能声称平台端已验证。
